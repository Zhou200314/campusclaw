# 文件上传逻辑与文件类型支持分析

> 分析对象：CampusClaw 迭代 1 的材料上传接口 `POST /api/materials`
> 分析方式：阅读实现代码 + 真实调用接口实测（脚本 `scripts/probe-file-types.mjs`）
> 结论一句话：**上传不限制文件类型；但"能否提取正文进入知识库、从而被搜索到"只覆盖文本类文件。**

---

## 一、文件上传逻辑

### 1.1 处理流程

```
客户端（教师登录后选文件，multipart/form-data）
   │
   ├─ ① requireAuth            会话 Cookie 校验       失败 → 401 UNAUTHENTICATED
   ├─ ② requireRole("teacher") 角色校验               学生 → 403 FORBIDDEN（在读文件前拒绝）
   ├─ ③ multer.memoryStorage   解析表单、文件进内存    超限 → 413；字段名非 file → 400
   │        限制：fileSize = UPLOAD_MAX_BYTES（默认 10 MB）、files = 1
   ├─ ④ safeFilename()         文件名净化              取 basename、替换 \ / : * ? " < > | 与控制字符、
   │                                                  截断到 120 字符并保留扩展名
   ├─ ⑤ 落盘                   uploads/<classId>/<uuid>-<净化名>
   │        班级取自服务端会话，请求参数无法指定班级
   ├─ ⑥ extractText()          正文提取                决定知识库写什么（详见第二、三部分）
   ├─ ⑦ BEGIN IMMEDIATE
   │        INSERT materials         （标题、正文、原文件名、大小、MIME、落盘路径、上传人、班级）
   │        INSERT knowledge_entries （material_id、标题、正文、来源文件名、班级）
   │     COMMIT
   │     任一失败 → ROLLBACK，并删除已落盘文件（不留半写入）
   └─ ⑧ 201 Created  { material: {...}, knowledgeEntry: {...} }
```

### 1.2 逐环节说明

| 环节 | 采用方案 | 为什么这样设计 |
| --- | --- | --- |
| 鉴权 | 会话 Cookie（HttpOnly + SameSite=Lax） | 同源站点，登出可立即失效；角色与班级来自服务端，不采信客户端声明 |
| 授权 | 教师可上传；学生仅可查看/下载 | 最小权限，少给一项能力就少一个垂直越权面 |
| 上传解析 | `multer` 内存存储 + 单文件 | 便于"校验通过才落盘"，且同一事务内可拿到完整内容做正文提取 |
| 大小限制 | `UPLOAD_MAX_BYTES`（默认 10 MB） | 由环境变量配置，超限 413 且不写库 |
| 文件名处理 | `path.basename` + 非法字符替换 + 长度截断 | 杜绝 `..\..\` 路径穿越；中文文件名按 UTF-8 还原，避免乱码 |
| 落盘路径 | `uploads/<classId>/<uuid>-<名>` | 目录即班级边界；UUID 前缀避免同名覆盖 |
| 数据写入 | 材料表 + 知识库表**同一事务** | 材料与知识条目要么同时存在，要么都不存在 |
| 返回 | 201 + 材料与知识条目 ID | 前端据此提示"材料 #5 与知识库条目 #1 已写入" |
| 下载 | `GET /api/materials/:id/download` | 同样走鉴权与班级过滤；`Content-Disposition: attachment` 强制附件，避免 HTML 被内联执行 |

### 1.3 失败路径

| 场景 | 状态码 | 响应体 |
| --- | --- | --- |
| 未登录 | 401 | `{"error":{"code":"UNAUTHENTICATED",…}}` |
| 学生会话上传 | 403 | `{"error":{"code":"FORBIDDEN","message":"当前角色无权执行该操作"}}` |
| 文件超限 | 413 | `{"error":{"code":"FILE_TOO_LARGE",…}}`（两表均不写入） |
| 无文件/空文件 | 400 | `{"error":{"code":"FILE_REQUIRED",…}}` |
| 字段名不是 `file` | 400 | `{"error":{"code":"UPLOAD_INVALID",…}}` |
| 跨班下载 | 404 | `{"error":{"code":"NOT_FOUND","message":"材料不存在"}}`（与不存在同形） |

## 二、支持哪种文件类型

上传接口**没有**扩展名或 MIME 白名单——**任何类型都能上传**。真正决定"是否支持"的是**正文提取**，它按以下顺序判定（实现见 `backend/src/knowledge.js`）：

1. **扩展名白名单**：扩展名命中 `TEXT_EXTENSIONS` → 按 UTF-8 解码全文；
2. **内容嗅探**：扩展名不在白名单时，取前 4 KB 判断"像不像文本"——**不含 NUL 字节**且**控制字符占比 < 5%** 即视为文本 → 同样提取；
3. **其余情况**：判定为二进制 → 不提取正文，知识库只写占位说明与来源文件名。

| 档位 | 判定依据 | 覆盖类型 | 知识库正文 | 可下载 |
| --- | --- | --- | --- | --- |
| **A 白名单** | `TEXT_EXTENSIONS` | `.txt` `.md` `.markdown` `.csv` `.tsv` `.json` `.log` `.yml` `.yaml` `.html` `.htm` `.tex` `.srt` `.vtt` | ✅ 提取（上限 20 万字符） | ✅ |
| **B 内容嗅探** | 前 4 KB 无 NUL、控制字符 < 5% | 任意扩展名（含无扩展名）的**纯文本** | ✅ 提取 | ✅ |
| **C 二进制** | 命中 NUL 或控制字符偏多 | `.docx` `.pdf` `.xlsx` `.png` `.jpg` `.zip` `.exe` 等 | ❌ 仅登记来源 | ✅ |

### 实测结果（`node scripts/probe-file-types.mjs`）

```
档位          文件            HTTP  extracted  知识库正文（前 34 字符）
------------------------------------------------------------------------------------------------
A 白名单       notes.md      201   true       "# 标题\n\n这是 UTF-8 文本。"
A 白名单       data.csv      201   true       "姓名,分数\n张三,95"
A 白名单       page.html     201   true       "<h1>标题</h1>"
B 内容嗅探     weird.xyz     201   true       "未知扩展名但内容是纯文本。"
B 内容嗅探     noext         201   true       "没有扩展名的纯文本。"
C 二进制       photo.png     201   false      "（二进制文件，未提取正文；知识库仅登记来源信息）来源文件：phot…"
C 二进制       report.pdf    201   false      "（二进制文件，未提取正文；知识库仅登记来源信息）来源文件：repo…"
C 二进制       doc.docx      201   false      "（二进制文件，未提取正文；知识库仅登记来源信息）来源文件：doc.…"
C 二进制       tool.exe      201   false      "（二进制文件，未提取正文；知识库仅登记来源信息）来源文件：tool…"
C 边界         png-min.png   201   true       "�PNG\n\u001a\n������…"      ← 不含 NUL 的最小二进制被误判为文本
C 边界         docx-min.docx 201   true       "PK\u0003\u0004wwwww…"       ← 同上
```

> 说明：真实 PNG / DOCX / PDF 的前 4 KB 通常含 NUL 字节，因此被判为二进制（C 档）；
> 但如果二进制文件恰好在前 4 KB 内没有 NUL（如某些小体积或特殊编码的文件），会被误判为文本并写入乱码——这是嗅探启发式的固有边界。

## 三、txt、md 以外的文件是否支持

要分两个层面回答，否则结论会互相矛盾：

### 3.1 上传 / 存储 / 下载层面：**支持**

接口不校验类型，所以 `.docx`、`.pdf`、`.xlsx`、`.png`、`.zip` 甚至 `.exe` 都能上传成功（实测均为 201），文件按班级目录落盘，之后可以正常下载。

### 3.2 知识库入库（正文可被搜索）层面：**只支持文本类**

| 类别 | 是否支持入库 | 具体类型 |
| --- | --- | --- |
| ✅ 支持 | 提取正文、可被 `GET /api/materials?q=` 搜到 | `.txt` `.md` `.markdown` `.csv` `.tsv` `.json` `.log` `.yml` `.yaml` `.html` `.htm` `.tex` `.srt` `.vtt`；以及**任意扩展名/无扩展名的纯文本** |
| ❌ 不支持 | 只登记来源，正文写占位说明，**按内容搜不到** | `.docx` `.doc` `.pdf` `.xlsx` `.pptx` `.png` `.jpg` `.zip` `.exe` 等二进制 |

**结论**：txt / md 之外仍然**支持**上面的 12 种文本扩展名，且靠内容嗅探还能覆盖"扩展名不认识但是纯文本"的文件；但**Word、PDF、Excel、PPT、图片等二进制格式均不支持正文入库**——它们能上传、能下载、能在列表看到文件名，但搜不到内容。这与课程 Non-goals 一致：知识库本迭代只负责"存"，不做检索与问答。

## 四、实测中发现的问题与改进方向

| 优先级 | 问题 | 证据 | 建议 |
| --- | --- | --- | --- |
| P1 | 只按 **UTF-8** 解码正文，GBK/GB18030 变乱码 | 上传 GBK 编码的"中文测试" → 入库为 `���Ĳ���` | 用 `iconv-lite` + 编码嗅探（BOM → UTF-8/UTF-16；无 BOM 回退 GB18030） |
| P1 | **扩展名优先于内容嗅探**：二进制改名成 `.txt` 会被当文本写入乱码；且 `node:sqlite` 在首个 NUL 处截断字符串 | 49 字节的 `fake.txt` 最终只存下 `"BIN"` 3 个字符 | 先做二进制判定（含 NUL 即二进制），扩展名只作辅助；写入前过滤含 NUL 的字符串 |
| P2 | 嗅探启发式存在边界：不含 NUL 的二进制被误判 | `png-min.png`、`docx-min.docx` 实测 `extracted=true` 且写入乱码 | 结合"魔术字节"（PNG/ZIP/PDF/%PDF/MZ）判定，或改用 `file-type` 库 |
| P2 | 无类型黑名单，可执行文件能上传落盘 | `tool.exe` 上传成功（201） | 增加 `.exe/.bat/.cmd/.scr/.dll` 黑名单，或隔离存储 + 强制 `application/octet-stream` 下载 |
| P2 | 无配额、无病毒扫描 | 仅限制单文件 10 MB | 按班/按人累计大小限额；对外部署接入 ClamAV 异步扫描 |
| P3 | 无去重 | 同一文件重复上传会写多条 | 按 `sha256(内容)` 在班级内去重 |
| P3 | 落盘在事务之前，进程崩溃可能留下孤儿文件 | 代码在异常分支 `unlink`，但崩溃不覆盖 | 改为"临时文件 → 事务提交 → rename 到位"，或加对账清理任务 |
| P3 | docx / pdf 不提取正文 | 实测 `extracted=false` | docx 用 `mammoth`、pdf 用 `pdf-parse` 提取 |

## 五、复现方式

```powershell
npm start                          # 启动服务
node scripts/probe-file-types.mjs  # 跑上面的类型实测表（运行后自动清理测试数据）
npm run capture:upload             # 上传/权限/事务的完整请求响应证据
```

相关实现文件：`backend/src/uploads.js`（上传链路）、`backend/src/knowledge.js`（类型判定与正文提取）、`backend/src/config.js`（大小上限等配置）。
