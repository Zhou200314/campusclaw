# 文件下载的权限与实现逻辑（分析）

## 结论

需要权限。下载接口 `GET /api/materials/:id/download` 与上传、列表走同一套访问控制，共三层校验：**登录态 → 班级归属 → 附件存在性**。任何一层不通过都不会返回文件。

## 实现逻辑（backend/src/uploads.js）

1. **登录校验**：`requireAuth` 中间件先执行，从请求 Cookie 中取会话令牌并到数据库比对；无 Cookie、令牌无效或已登出 → **401**，响应体只有 `UNAUTHENTICATED`，不含材料信息。
2. **取班级边界**：班级取自会话（`req.user.classId`），不接受任何请求参数指定班级，因此无法通过改 URL 参数的方式越权。
3. **按班级查库**：执行 `SELECT * FROM materials WHERE id = ? AND class_id = ?`，把"班级"写进 SQL 条件，而不是查出来再在代码里判断。查不到（跨班或确实不存在）→ **404**，且响应体与"不存在"完全一致。
4. **检查附件**：记录中没有 `stored_path`，或磁盘上文件已丢失 → 同样 **404**。
5. **返回文件**：用 `res.download(磁盘绝对路径, 原始文件名)` 返回，响应头为 `Content-Disposition: attachment`，强制按附件下载而不是在浏览器内联打开；中文文件名通过 `filename*=UTF-8''...` 传递，浏览器显示为原名。磁盘路径不会出现在响应里。

## 实测结果（8 种场景）

| 场景 | 结果 |
| --- | --- |
| 未登录下载（无 Cookie） | **401** UNAUTHENTICATED |
| 本班教师下载本班材料 | **200**，返回文件内容与上传时一致 |
| 本班学生下载本班材料 | **200**（学生只有查看/下载权限，允许） |
| 跨班下载（1 班教师取 2 班材料） | **404** 材料不存在 |
| 不存在的 ID（99999） | **404** 材料不存在（与跨班同形） |
| 非法 ID（abc） | **404** 材料不存在 |
| 种子材料（列表有文件名但磁盘无附件） | **404** 材料不存在 |
| 登出后用旧 Cookie 下载 | **401**（会话行已删除） |

## 设计要点

- **跨班与不存在同形**：两者都返回同一个 404 文案，攻击者无法通过状态码或文案差异探测别的班有哪些材料。
- **角色不额外限制下载**：教师与学生都能下载，这正是本迭代的角色边界（学生＝查看＋下载，教师＝上传＋查看＋下载）；上传接口才是按角色区分的。
- **不区分上传者**：同班任何成员都能下载本班材料，下载权限挂在"班级"而不是"上传人"上。
- **附件而非内联**：即使有人上传 HTML/SVG，也不会被浏览器当作页面执行，降低 XSS 风险。
- **磁盘名与展示名分离**：磁盘上是 `<uuid>-<净化名>`，展示与下载用数据库里的原始文件名，既避免同名覆盖，也不泄露服务器目录结构。

## 已知不足

- 种子材料在列表里显示了文件名，但磁盘上并没有对应文件，下载时返回 404；"材料存在但没有附件"与"材料不存在"使用同一条文案，语义上不够精确，建议种子阶段就写入真实文件，或列表里标注"无附件"。
- 下载没有独立的频次限制、审计日志与水印，也未做单文件下载次数统计；如需对外服务可后续补充。
- 未做权限缓存，每次下载都会查一次库与一次磁盘 `existsSync`；单实例场景下开销可忽略。
