# Design: add-traceable-vector-retrieval

## Context

检索必须满足三个约束：只能检索本班材料、命中必须能回溯到原文、没有依据时不得编造。
因此设计围绕"班级只来自会话""正文留在关系库""无切片不调用模型"三条展开。

## Decisions

### D1 切片正文留在关系库，向量库只存向量与标识

`knowledge_chunks` 保存 `chunk_text`、字符偏移与状态；向量与切片同表同行（主键一致），检索命中后直接回表取正文。
换成独立向量库时，向量主键与 `knowledge_chunks.id` 相同，payload 只放标识，不必重复保存正文。

### D2 三种切分策略，默认 auto

`auto` 固定 800 字窗口与 80 字重叠，优先在空行、换行、句号处断开；`custom` 允许 100–2000 字与 0–50% 重叠并支持预处理，预处理只作用于切分输入，不改写原文；`hierarchy` 按 `#/##/###` 分章，过长章节再按窗口切分。
未指定策略时按 `auto`；重建索引使用请求中的策略，已入库材料不会自动重新切分。

### D3 关键字检索用 2-gram 倒排

中文全文检索在关系库中依赖 ngram 分词，切片入索引时按 2-gram 建倒排（`chunk_grams`），查询时按 IDF 加权并对切片长度做归一化。关键字模式不调用嵌入服务。

### D4 向量检索阈值为 0.35，混合模式用 RRF

余弦相似度低于阈值（默认 0.35）的候选丢弃；混合模式把两路各自的名次按 `1/(k+rank)`（k=60）相加，**不把两路分数直接相加**；缺席的一路不贡献分数。

### D5 班级只从会话取，两条路径都要过滤

关键字与向量路径都使用会话中的 `class_id`：关键字在 SQL 条件里过滤，向量在候选过滤后回表时再按同一班级条件查询一次。请求体或查询参数里的班级编号解析后即刻丢弃。
跨班检索对外表现为**无命中**，不使用 403/404，避免泄露资源归属。

### D6 无依据不调用模型

`POST /api/ask` 先做混合检索取前 4 条；一条都没有时直接返回固定文案与空 citations，完全不访问对话服务。
有命中时才把"材料标题 + 切片序号 + 切片正文"按编号交给模型，且服务端写入 system 提示、丢弃客户端注入的 system 消息。

### D7 嵌入与对话均为可插拔 provider

两者都对接 OpenAI 兼容协议，因此同一份代码可用阿里云百炼、硅基流动、Ollama 或课程网关，只需改 `.env`。
未配置时降级为本地确定性伪向量与摘录式回答，用于跑通链路；此时向量检索的语义能力明显变弱，属已知限制。

### D8 失败语义

空查询 400；嵌入服务未配置或调用失败时关键字仍可用，向量与混合返回 503，不伪造相似度；嵌入失败时材料与切片保留、切片标记 `failed`；换嵌入模型时按 `embedding_model` 识别并自动重建索引。

## Alternatives considered

| 方案 | 结论 |
| --- | --- |
| 分数归一化后加权求和 | 否决。换嵌入模型需重新标定权重，RRF 只依赖名次，更稳 |
| 只保留混合模式 | 否决。向量库故障时无法退化为关键字检索 |
| 把正文复制进向量库 payload | 否决。正文出现两份副本，且摘录一致性变差 |
| 客户端传班级编号 | 否决。隔离必须由服务端会话决定 |
| 无依据时让模型自行声明"不知道" | 否决。提示约束可能被忽略，可追溯性下降 |
